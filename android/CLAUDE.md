# android/ — MealPlan+ Android app

Kotlin · Compose (Material 3) · Room · Hilt · single-Activity. MVVM + Repository, per Now-in-Android.
`Compose UI → @HiltViewModel (StateFlow) → Repository (Flow<T>) → Room DAO / Retrofit`.

## Commands
- Unit tests (JVM, no emulator): `./gradlew :android:testDebugUnitTest`
- Instrumented DAO tests (in-memory Room): live in `android/src/androidTest/`

## Where things live
`data/{healthconnect,local,model,remote,repository}` · `di/` (Hilt modules) · `notification/` (AlarmManager) · `ui/{screens,components,navigation,theme}` · `util/` · `widget/` (Glance) · `work/` (SyncWorker).
Screens are one package each: `Screen.kt` + `ViewModel.kt`. Full package map + entity list: `docs/DATABASE_SCHEMA.md`.

## Hard rules — never break
1. **No destructive Room migrations.** IMPORTANT: always add an explicit `MIGRATION_X_Y` in `DatabaseModule.kt`; never `fallbackToDestructiveMigration`. Keep `android/schemas/` in sync (target v27, 16 entities). Migrations need human approval.
2. **Never delete system food rows on re-seed.** `DatabaseSeeder` is upsert-only — preserves FK refs from `meal_foods` / `logged_foods`. Re-seed is version-gated by DataStore key `systemFoodsVersion`.
3. **Notifications: AlarmManager, not WorkManager.** WorkManager is only for `SyncWorker`. Do not re-add the deleted notification workers.
4. **Notifications fire only when the slot is not yet logged** — enforced by `shouldPostMealAlarm()` in `NotificationAlarmReceiver`; don't bypass it.
5. **`planned_slots` is the source of truth for day planning.** Load it first; fall back to `day_plans.template_diet_id` → `diet_slots` only for slots not yet in `planned_slots`.
6. Firebase = Auth/Crashlytics/Remote Config/Analytics only (see root zero-billing rule).

## Conventions
- Dates stored as `Long` (epoch ms at UTC midnight). Use `LocalDate.toEpochMs()` / `Long.toLocalDate()` in `util/DateUtils.kt`.
- `slotType` lives on `diet_slots`/`planned_slots`, not on `Meal` (a meal is a reusable food collection).
- `user_id` only on `day_plans`, `daily_logs`, `health_metrics`, `grocery_lists`. Meals/diets are app-global.
- DataStore `"settings"` store (`ThemePreferences.kt`) holds all user prefs (theme, notifications).

## Notifications (AlarmManager)
5 types in `NotificationAlarmType` (BREAKFAST, LUNCH, DINNER, STREAK, WEEKLY_PLAN), stable `requestCode` 1–5. One-shot `setExactAndAllowWhileIdle`; receiver re-schedules next fire. `SCHEDULE_EXACT_ALARM` needed on API 31+. Single entry point: `NotificationAlarmBootstrapper.scheduleAll(context)`.

## Health Connect
Read-only integration (free, no cloud cost): steps + calories burned + latest weight. `HealthConnectManager` (raw SDK) → `HealthConnectRepository` (safe wrapper, returns defaults when unavailable). 3 read perms in manifest. Android 14+ always available; 9–13 needs the Play Store app.

## Test patterns
- Coroutines: `@BeforeClass` sets `Dispatchers.setMain(UnconfinedTestDispatcher())`.
- Mock objects with `mockkObject` / `mockkObject(NotificationPreferences)`; always `unmockkObject` in `@After`.
- Flows via Turbine: `viewModel.uiState.test { … cancelAndIgnoreRemainingEvents() }`.
